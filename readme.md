# Freight Rate Prediction

A machine learning pipeline that predicts freight load rates (posted_rate) from load, route, and market features, built for the Machine Learning Engineer take-home assessment.
The model is a scikit-learn `HistGradientBoostingRegressor` trained on 48,000 labeled loads, validated with a chronological (time-based) holdout, and used to generate predictions for 12,000 unlabeled loads plus a fixed 31-day December scenario chart.

## Results

Evaluated on a October 2025 chronological holdout (trained on January–September 2025):

| Metric | Value |
|---|---|
| MAE  | $168.42 |
| RMSE | $668.86 |
| MAPE | 7.88% |

The final model is retrained on all 48,000 labeled rows before generating submission predictions.

## How to Run

```bash
python -m pip install -r requirements.txt
python train_model.py
```

This will:
1. Load `train-test.csv` and `validation.csv`.
2. Engineer date and route features (month, day-of-week, day-of-year, distance-per-weight, route lat/lon deltas).
3. Hold out October 2025 and evaluate on it (prints MAE / RMSE / MAPE).
4. Retrain on the full labeled dataset.
5. Predict all 12,000 validation loads → `validation_predictions.csv`.
6. Predict all 31 December scenarios → updates `december-chart-inputs.csv`.

Then verify the outputs with the supplied scorer:

```bash
python score.py --predictions validation_predictions.csv --december-predictions december-chart-inputs.csv
```

This validates both files and writes `scorer_results/candidate_december.png`.

## Approach Summary

- **Validation strategy:** Chronological split (train on Jan–Sep 2025, hold out Oct 2025) rather than a random split, since the actual validation/December data occurs after the training period — a random split would leak future information and overstate performance.
- **Data quality:** Training and validation data each contain missing values (674 and 414 cells respectively). Numeric columns are median-imputed; categorical columns are most-frequent-imputed. All preprocessing is fit only on training data via a `Pipeline` + `ColumnTransformer`, so validation/prediction data never influences the imputation or encoding statistics.
- **Model:** `HistGradientBoostingRegressor`, chosen for its ability to capture nonlinear interactions between distance, weight, route, equipment, and market signals without manual feature engineering, and its efficiency on a dataset this size.
- **December scenarios:** The December input file omits several training columns (coordinates, `market_index`, `quote_signal`); these are added back as missing values so the same trained pipeline can impute and predict them consistently.

Full detail — including a known limitation around the December chart's flatness caused by the missing December columns, and ideas for future improvement — is in `Freight_Rate_ML_Assessment_Report.docx`.
